# M3.1 评测方案与前置条件交互修正

状态：`done`。本修正已在 M4 Runtime 接入前完成，运行协议只引用不可变 Profile Version，不再引用可漂移的 Profile 或独立 Evaluator 用户对象。验收记录见 [M3.1 验收证据](m3.1-acceptance-evidence.md)。

## 1. 决策

- 用户只管理“评测方案”，不单独创建 Evaluator。
- Exact、Contains、Regex 和 JSON Schema 是系统内置评分规则类型；LLM Judge 和自定义代码后续作为规则 Adapter 接入。
- Evaluation Profile 保存可变元数据；Profile Version 固化规则、聚合策略、通过阈值和 Content Hash。
- Evaluation Run 直接引用 `EvaluationProfileVersionId`，历史运行不受后续方案修改影响。
- 当前处于开发阶段，直接重写未发布的 `0009_datasets_evaluations.sql`，不保留旧 Evaluator 表和 API 兼容层。

## 3. 前置条件规则

- 缺少数据时按钮保持可点击。
- Dialog 同时列出已完成和缺少的项目。
- 有权限时跳转到明确创建入口；无权限时提示联系管理员。
- 加载、提交和重复请求保护仍可禁用按钮。
- 后端继续校验所有依赖，前端提示不构成安全边界。

首批覆盖 Application、Application Deployment、Evaluation Run、Workflow 发布、Dataset Version、Skill 启用和 Model 编辑。

## 4. 验收

- 空库和 M1 Schema 追加 Migration 通过。
- OpenAPI 不再出现 `EvaluatorResponse`、`CreateEvaluatorRequest` 或 `/evaluators`。
- Profile 创建至少支持两条内嵌规则，并返回不可变 v1。
- Evaluation Run 请求和响应只使用 `evaluationProfileVersionId`。
- 空 Dataset 点击发布时显示依赖 Dialog，并能直接打开新增 Case。
- 前置条件组件覆盖缺少依赖和依赖齐备两种单元测试。
- 临时 Kubernetes E2E 通过并自动删除 Namespace。
