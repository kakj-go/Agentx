# M2.1 资源中心重构与全局 E2E 计划

## 1. 目标和当前状态

- 状态：`done`。M2.1 主体和交互收口均已完成，统一资源授权、模型连接状态、MCP Schema 可视化、Skill 富文本编辑和 Dialog 自适应布局已通过临时 Kubernetes Playwright 验收。
- 目标：用 MCP Server、自动发现的 MCP Tool 和在线 Skill Workspace 替换旧 Tool/ZIP-only Skill 模型，并建立临时 Kubernetes Playwright 验收门禁。
- 数据策略：保留 M1 Migration `0001` 至 `0003`，直接重写开发阶段的 `0004` 至 `0007`；不兼容旧 M2 数据、API、Workflow Definition 或 PVC。
- 阶段边界：本批次只完成控制面和连接调试，不实现 Workflow Runtime、Agent Loop、Skill Runtime 或 CubeSandbox。

## 2. 领域决策

- 资源菜单固定为 Credential、Model、MCP Server、Skill、Knowledge 和 Memory。
- MCP Server 是连接；MCP Tool 由 `initialize` 和 `tools/list` 自动发现，用户不能手工创建或修改 Schema。
- Workflow Definition 和 Skill 依赖只允许 `mcp_tool`，不再接受 `tool`。
- Sandbox 不属于 MCP、连接或 Tool Runner，阶段 10 单独实现 CubeSandbox Connection 和 Sandbox Profile。
- Skill 是文件工作区。根目录 `SKILL.md` 必须存在且不可删除，`name` 和 `description` frontmatter 必填；界面在正文上方独立编辑描述并由后端生成规范 frontmatter。只有 Markdown 可在线编辑，其他文件只允许上传和预览。
- Model 配置编辑创建不可变 Deployment Revision；Credential 名称编辑不创建 Secret Version。
- Echo MCP 只进入本地和 E2E Overlay。LightRAG、Mem0 作为可选 Addon，不进入默认生产 Base。

## 3. 稳定接口

- Model：Provider PATCH、Alias PATCH、Deployment Revision 创建和 Deployment History 查询。
- Credential：现有 PATCH 支持名称和状态的乐观锁更新，响应不包含 Secret。
- MCP：`/api/v1/mcp/servers`、发现、Tool Policy、Debug Invoke 和连接测试。
- Skill Workspace：Entry 创建、移动、重命名、删除、Markdown Revision、上传、预览和发布 Version。
- Workflow 资源引用：`resourceType=mcp_tool`，发布快照包含 MCP Server/Tool Version、Schema Hash、Credential 和策略。
- 所有写操作携带实体 Version 或 Workspace Revision；冲突使用结构化 `409` 错误。

## 5. 失败、安全和完成门禁

- MCP 调试不创建 Workflow Execution，不记录参数/响应正文，只记录 Hash、状态和耗时。
- Credential 明文不得进入响应、审计、日志或 OpenAPI 示例。
- Skill 路径拒绝绝对路径、`..`、重复名称和 Zip Slip；删除被引用文件必须失败。
- 业务按钮必须由 Playwright 真实点击，API/数据库只能准备环境和校验证据。
- 所有任务、快速检查和临时 Kubernetes E2E 全部通过后，M2、阶段 03/04 和 MVP 步骤 3/4 才能恢复 `done`。
