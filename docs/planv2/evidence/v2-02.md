## 交付与边界

- `agentx-bundle-builder` 从固定 Workflow Version 生成确定性 `ExecutionSpecBundleV1`，冻结编译 IR、Node Manifest、输入输出、运行策略和传递依赖闭包；JCS/SHA-256、Ed25519 签名、固定子版本、递归、缺失对象、未知节点版本和 Capability 拒绝均有自动化测试。
- `migrations/control/0002_bundle_publishing.sql` 增加 Bundle、对象副本、Publish Attempt 和可 Claim 的 Control Outbox；`migrations/runtime/0002_bundle_publishing.sql` 增加发布 Receipt、Runtime Object、Bundle Reference/Hold/GC，以及 Invocation/Execution/Snapshot 的 Bundle、Admission Epoch 和结构化结果字段。V2-01 的三个 `0001_initial.sql` 未修改，133 张旧表处置统计保持 `58/34/39/2`。
- `contracts/v2-schema-table-ownership.json` 对 V2-02 的 11 张增量表登记 Plane、Writer、Reader、跨面契约、保留规则和 owning task。边界检查器把增量表合并进 SQL 所有权扫描，并以正向/负向 Fixture 验证漏登、越域或双 Writer 会失败。
- `platform-control --roles=api,publisher` 以异步 Publish Attempt 推进 `building → copying → preparing → prepared → activating → active/rejected`，外部 I/O 位于 Claim 事务之外，完成写入校验 Owner/Fencing Token。API Key 创建、轮换、撤销和 Application Disable 通过单调 Admission Epoch 投影。
- `runtime-gateway` 实现对象上传、Admission、Prepare、Activate、Rollback、Disable 和 Runtime Query v1；写接口验证 RS256 Service JWT、Role/Scope、版本、Tenant、JCS Hash、Ed25519 签名、对象完整性、Idempotency、Head CAS 和 Activation Sequence。
- `runtime-gateway` 只读取 Runtime MySQL 和 Runtime OSS；其 Settings、Deployment 环境和 Secret 引用均不含 Redis。`workflow-runtime` 和 `workflow-worker` 的基础路径只读取 Runtime MySQL/Redis/OSS。Invocation 事务固定 `bundle_id/admission_epoch` 并创建 Invocation、Execution、Snapshot、Command、Outbox 和 `active_execution` Reference；Redis 只负责派发，Runtime MySQL 同步保存终态与输出。
- Application 原页面复用既有组件增加发布状态、脱敏错误、Retry 和 Rollback；没有新增页面、路由、设计令牌或样式体系。浏览器 API 保持既定 URL，Deployment 创建返回异步发布结果。
- Bundle GC 使用 100 条批次、30 秒 Lease 的 Mark/Sweep 骨架；Active、Prepared、Head、Reference 和 Retention Hold 均阻止删除。Ready 但从未绑定 Bundle 的正式对象在一小时后进入对象级 Mark/Sweep；Prepare 与 GC 通过对象行锁和 `ready/deleting` 状态互斥。对象删除失败保存 GC Item 并可重试，删除后的 immutable upload 可用原幂等请求重新建立。Session、Wait、Checkpoint/Fork 的完整运行语义不在本阶段完成范围内。

## E2E-V2-001：发布与激活

执行命令：

```powershell
.\scripts\v2-02-e2e.ps1 -RunId 20260813v202p -ScaleDownDevelopment -KeepOnFailure
```

Docker Desktop Kubernetes 使用以下唯一临时 Namespace；脚本沿用 V2-01 基础设施前缀，但 Run ID 唯一：

```text
agentx-v2-01-control-20260813v202p
agentx-v2-01-runtime-20260813v202p
agentx-v2-01-observability-20260813v202p
agentx-v2-01-deps-20260813v202p
```

动态结果：

- Application Deployment 创建异步 Publish Attempt。强退场景中 Runtime 已提交 Activate Receipt，而故障代理仍悬挂 Publisher HTTP 请求；测试把原 Publisher Pod 强制缩容为零，释放代理后由新 Publisher 以原 Idempotency Key 接管。Runtime 只有一条 Activate Receipt，Control 只有一个 Bundle/Head/Attempt 终态，旧 Owner 的 Fencing 写入被拒绝。
- Prepare-only Bundle 在 Activate 前没有生产 Route，不能接收 Invocation。
- Runtime 对象上传完成后删除 Control OSS 源对象，Runtime Bucket 内不可变副本仍可读取。
- 发布第二个 Bundle 后创建在途 Execution，再回滚到第一个 Bundle；在途 Execution 始终固定第二个 Bundle，新 Invocation 使用回滚后的 Head。
- API Key 撤销推进 Admission Epoch；撤销后的 Key 无法创建 Invocation。随后请求 Rollback 被结构化拒绝，Runtime 中已撤销 Key 和更高 Epoch 均未恢复。
- Control 恢复后，两个 Bundle 各只有一条 Control 事实，四个发布/回滚 Attempt 各一条，Control Outbox 的 `pending/processing/failed` 残留为零。

以上覆盖正式 E2E-V2-001 的 V2-02 发布切片；完整产品资源、Trigger 和 Runtime 能力仍按后续阶段扩展。
