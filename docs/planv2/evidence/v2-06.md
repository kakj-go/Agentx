## 3. 06A 实现证据

- 公共 `agentx-mysql-lease` 使用 Pod UID 注入的 `AGENTX_INSTANCE_ID`，本地运行才生成 UUID；MySQL Lease 固定 30 秒、Heartbeat 10 秒、批量上限 100，过期判断使用 `UTC_TIMESTAMP(6)`。
- Claim、Heartbeat、Complete 和 Fail 统一校验 Owner、Fencing Token 和未过期 Lease；旧 Token 影响行数为 0 并返回 `LeaseLost`。外部 HTTP、Redis、OSS、Vault、ClickHouse 和 Provider I/O 均位于 Claim 事务提交之后。
- `migrations/control/0006_horizontal_scalability.sql` 和 `migrations/runtime/0006_horizontal_scalability.sql` 为实际 Claim 条件补齐覆盖索引；`0001～0005` 未修改，也未增加业务权威表。
- 六类后端常驻应用统一提供 Live、Ready、Drain 和低基数 Metrics：Live/Ready 位于 `8080`，仅供 `preStop` 使用的 Drain 位于 `9091`，Metrics 位于 `9092`。Drain 立即使 Readiness 失败并拒绝新写，后台 Role 停止 Claim，已领取工作在 45 秒上限内继续 Heartbeat，Pod 终止宽限为 60 秒。Web Console 的 Nginx 使用等价的 Live/Ready 与 `nginx -s quit` preStop，并由 Resource Metrics 驱动 CPU HPA。
- 七类常驻 Deployment 均配置 Startup/Readiness/Liveness、`preStop`、RollingUpdate、PDB 和 HPA。应用指标通过独立 `9092` Service 暴露且只允许 Prometheus 访问；Web Console CPU HPA 使用 Resource Metrics。
- 紧凑 Profile 的 Min/Max 为 `2/4`。Runtime Gateway、Workflow Runtime、Worker 和 Sandbox Manager 同时扩至 4 个副本时，Runtime MySQL 最大连接预算为 `4×8 + 4×10 + 4×6 + 4×2 = 104`，不超过 Profile 上限 105 和 MySQL 151 连接的 70%。
- Bundled Prometheus 使用静态 DNS 发现；Prometheus Adapter 只读取 Prometheus，Metrics Server 只访问 Kubernetes API 与 Kubelet 所需端口，二者均没有 MySQL、Redis、OSS、Vault 或 ClickHouse Credential。
- `RoleProgressWatchdog` 覆盖 Publisher、Admission Outbox、Projector、Retention、Gateway 依赖探测、Runtime 后台 Role、每个 Worker Capability、Sandbox Reaper 和 Trace Consumer；90 秒无进度才使 Liveness 失败，依赖故障本身不会触发进程重启。
