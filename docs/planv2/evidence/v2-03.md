## 交付与边界

- `migrations/control/0003_runtime_gateway.sql` 和 `migrations/runtime/0003_runtime_gateway.sql` 增加 Trigger Revision、用户运行准入、精确 Application Grant、Trigger Operation，以及 Session/Message/Invocation/Event/Artifact/Idempotency 所需字段和索引；V2-01 `0001_initial.sql` 保持不变，原 133 表处置统计保持 `58/34/39/2`。
- `agentx-runtime-contracts` 冻结类型化 Trigger、Runtime Policy、Session Policy、用户准入、用户 Grant、Session Query/Upgrade 和公共 Gateway DTO。所有 v1 DTO 拒绝未知字段和版本 `2`；Trigger 枚举变体字段使用公共 camelCase Wire Format。
- V2 `runtime-gateway` 是 `/gateway/v1` 和 `openapi/trigger-gateway.json` 的唯一生成源。V2-02 临时 `/runtime/v1` 不存在；Internal API 仍只暴露为 `/internal/runtime/v1`，不进入 Runtime Ingress。
- Runtime Gateway 的认证、Route、Session、Message、Invocation、Artifact、SSE、Cancel 和 Resume 只使用 Runtime MySQL、Runtime OSS、只读 Vault，以及用于 SSE 唤醒的 Runtime Redis。`invocation_events.sequence_number` 是 SSE 权威 Cursor；Redis 丢失时每秒回查 MySQL。
- Gateway Redis Client 被封装在 `sse_wakeup` 模块；边界检查器拒绝 Gateway 其他模块直接引用 Redis，并有负向 Fixture。Workflow Runtime/Worker 的 Runtime Queue Redis 仍按其独立职责使用。
- API Key 使用 Runtime Hash/Admission Epoch；浏览器 Access Token 使用独立 RS256 当前/上一 `kid` 公钥，并校验用户状态、Token Version、Tenant 和精确 Application Grant。Service JWT、用户 JWT 与 Bundle Ed25519 Key 没有复用。
- Session 支持 `pinned`、`follow_deployment` 和 `manual_upgrade`。Message/Invocation/Execution/Command/事件在 Runtime MySQL 事务内收敛；响应丢失后以同一 Idempotency Key 返回原业务事实。
- Artifact 以流式 Multipart 写 Runtime OSS 临时对象，校验后转正式 Key；幂等重放返回原 Artifact，冲突返回稳定错误，临时对象被清理。
- `workflow-runtime --role=trigger` 使用 Runtime Binding、30 秒 Lease、10 秒 Heartbeat 和 Fencing Token处理 Schedule/Poll/Lifecycle。Schedule 固定 IANA 时区、`skip/fire_once`、DST 和时钟回拨语义；Webhook 使用版本化 Vault KV v2 引用和 HMAC-SHA256，不回退 Control 数据或明文 Secret。
- V2 Profile 使用不同的 Control/Runtime Host，Runtime Ingress 只路由 `/gateway/v1`；Web 运行时注入 Runtime Base URL，不由 Web Nginx 代理生产 Gateway。页面路由、布局、组件、样式和设计令牌没有变化。
