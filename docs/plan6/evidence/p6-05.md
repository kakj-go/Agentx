# P6-05 Trace证据

- Runtime/Observability契约增加`plugin_operation`和`plugin_content`，不为业务插件增加枚举。
- Runner使用AsyncLocalStorage实时发送started/content/event/finished并保持嵌套Promise父子关系；宿主HTTP/Model调用保存插件父Span实体与runtimeCallId。
- 业务内容按包声明 Schema 检查，Preview 复用平台预算与脱敏；大内容在 2 秒诊断预算内外置为 Artifact，失败只记录诊断，不影响业务结果。
- UI按`nodeType/typeVersion/bundleDigest/contentType/contentVersion`获取冻结renderer，停用后仍可加载历史；缺组件时回退标准JSON。
- Runner 限制 64 Span、16 层深度、每 Span 32 内容/128 事件/64 属性；测试覆盖预算耗尽、同类型多内容和并发 Promise 父子上下文。
- 宿主调用标记 `plugin_host_call/platform_runtime_call` 与 `costIncludedInParent=false`，插件诊断标记 `meteringSource=plugin_diagnostic`，避免把插件自报成本重复计入平台调用。
- 本地和临时 Kubernetes 均在执行结束前查询到 `plugin_operation`，真实页面加载 `Mapped items: 0/1` 与大 Artifact；pytest 将 ClickHouse 缩至 0 后验证业务结果仍可读和 Trace 明确降级，恢复后瀑布重新可用。
