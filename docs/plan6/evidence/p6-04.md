# P6-04 Runner与部署证据

- JSON-RPC覆盖initialize、execute、cancel、设计时方法、通知、反向宿主请求、未知方法/API和8MiB消息门禁。
- Worker进程池按bundle digest复用，一进程同时一个调用；Semaphore限制总Node进程，空闲TTL回收。设计时容量独立限制为2。
- `ctx.http/model/credentials/artifacts`由Rust执行；外部写调用使用Runtime Call幂等账本，RPC `-32021`保留Outcome Unknown。
- Attempt deadline覆盖排队、装载与执行；Worker Future被取消或Lease/Drain失败时Guard终止进程树。Windows Job Object和Linux进程组分别实现。
- Worker向Runner发送的deadline使用RFC3339时间戳，Node端和Rust端采用同一绝对期限。
- Windows测试`timeout_reclaims_the_plugin_process_tree`通过；Runner池测试证明同摘要复用PID；容器握手测试证明Node 24.20.0、协议1、SDK1和部署参数生效。
- Values 包含 `pluginMaxProcesses=8`、`pluginIdleSeconds=60` 和 `pluginMemoryMb=96`，Worker 启动时校验精确 Node 版本与 Runner 文件，并以 `--max-old-space-size` 执行单进程预算。
- Runner 每次调用使用新模块 URL，清理 timeout/interval/immediate/process listener；测试覆盖 50 次热调用、后台任务、协议污染和池恢复。
- Kubernetes 故障插件覆盖 background/crash/hang/orphan/recover；Worker 滚动替换后由冷进程完成原 Execution，无孤儿进程。容器 PID 1 为 `tini`，Worker 不含 `AGENTX_CONTROL_*` 凭据。
