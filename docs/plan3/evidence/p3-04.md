状态：`done`

审计更新：2026-08-25。Agent Core Contract 已破坏性升级为 `1.1`，Canvas Attachment 的生产 Adapter、冻结 Bundle、统一 Registry 和 Runtime Grant 已进入唯一 Agent Loop；P3C-001～P3C-010 均已关闭，真实 Kubernetes 已通过 Workflow→Work Package/Bundle→Worker→Agent Core→Attachment 主链。本阶段仍不包含跨 Session 可信 Subject Memory、自动 Transcript 写入、完整 Compaction 或多 Lane Session。

## 1. 契约与控制面

- `crates/agentx-runtime-contracts/src/package.rs` 固定 `AgentAttachmentRegistryV1`、External Context、Tool Origin/Replay Policy、Authorization Evidence 与 Knowledge Citation；Bundle 相同输入保持确定性。
- `crates/agentx-runtime-contracts/src/process_session.rs` 固定 Process Session、Lease、Frame、Control 与错误契约；生成 Schema 位于 `schemas/runtime-v1/`，内部接口位于 `openapi/runtime-internal-v1.json`。
- `services/platform-control/src/mcp_api.rs` 只接受封闭 tagged transport。`stdio` 必须固定 Runtime Sandbox 精确版本，HTTP/SSE 禁止携带该字段；旧平面 `transport + endpoint` 不再兼容解析。
- `mcp_tool_versions.server_version_id` 固定发现时 Server Version；更新 Server 不会把旧 Tool 重新关联到当前版本。
- Studio 已将 Runtime Sandbox 与 Credential 切换到统一 Resource Picker，stdio 字段按 Transport 条件显示，环境 Credential 使用结构化可增删行且不接收 Secret 明文。配置期依赖授权主体固定为 MCP Owner Department，运行期仍使用 Workflow Service Identity；两类 Grant 不互相替代。决策见 [P3-04 外挂能力配置期授权 ADR](../p3-04-attachment-authorization.md)。

## 2. Process Session 与三种 MCP Transport

- `services/agentx-v2-runtime/src/sandbox_process.rs` 提供 `start/write/read/wait/interrupt/terminate/reconcile`，同一 Agent Run + Server Version 只有一个活跃进程。
- stdio 命令只在独立 MCP Runtime Sandbox 中通过结构化 argv 启动；Vault Secret 明文只在启动内存出现，不进入 Bundle、数据库、Ledger 或 Trace。
- stdout 仅接受单行、最大 1 MiB 的 JSON-RPC Frame；stderr 独立为诊断流；超过 64 KiB 的 Frame 内容外置为 Runtime Artifact。
- `services/agentx-v2-runtime/src/worker_runtime/mcp.rs` 与 `worker_runtime_provider.rs` 统一 Streamable HTTP、Legacy SSE 和 stdio。Legacy SSE 使用真实长连接、Endpoint Event、分片响应和 Session 复用，不再退化为普通 POST。
- Agent Workspace 与 MCP Runtime Sandbox 使用不同 Repository、Identity、Lease、Credential、NetworkPolicy、目录和清理状态。

## 3. Skill、Knowledge、Memory 与统一 Registry

- `RuntimeSkillProgramV2` 固定入口指令、全部签名资产、Content Hash 和递归依赖；Worker 不从用户目录、Git、npm 或网络动态发现 Skill。
- Skill 指令在首轮 Model Effect 前按稳定顺序注入一次；`skill_resource` 只读取 Bundle 中签名资产，不赋予 `read/write/edit/bash`。
- 每个 Knowledge Binding 注册独立 `knowledge_search_<resource_uuid>`，结果携带 Resource/Document/Chunk/Title/URI/Score Citation，并以不可信 Tool Result 和有界 Artifact 进入模型上下文。
- Memory 按 Binding Operation 与 Namespace Access Mode 暴露 `memory_recall` 和/或 `memory_write`；P3-04 Scope 由 Runtime 派生为 Agent Run，write 为 `Never` Replay，不跨 Execution 自动召回。
- Worker 的 `AgentToolRouter` 统一路由 Workspace、MCP、Skill Resource、Knowledge 与 Memory。发布阶段拒绝名称冲突、非法 Schema、重复绑定、循环/冲突依赖和授权闭包缺失；运行时再次防御校验。

## 4. Grant、恢复与撤权

- Run 开始、Registry 构造、每个外部 Effect 和 stdio Process Start/恢复前均验证精确 Resource Version、Operation、Grant 和 Policy Epoch。
- Control 离线时只使用 Runtime Last Known Good Projection；超过最大陈旧窗口拒绝执行。
- Run 中途撤权按 Tool 隔离：被撤权 Tool 不再出现在后续 Model Turn，不相关 Tool 与 Agent Workspace 保持可用。
- MCP/Memory Write 和未知 stdio Effect 不盲目重放；stdio 已按冻结 Tool Replay Policy记录 `none/idempotent/irreversible`，任何已发送 Frame 均先读取持久化 Frame Ledger 按 JSON-RPC ID 对账，通用 HTTP Ledger 不直接重发。Frame/Runtime Call Ledger 使用稳定 Operation、Effect、Idempotency 与 Fencing 身份。
