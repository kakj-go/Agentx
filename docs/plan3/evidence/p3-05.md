## 1. 已落地契约

- `crates/agentx-agent-core/src/session.rs`、`session_store.rs` 固化 `application_session` 与 `invocation` 隔离键、trusted Subject、Entry/Register/Usage、append-only 和 CAS/Fencing 规则。
- `migrations/runtime/0001_initial.sql` 的 Agent Session 初始 Schema 包含 `agent_session_entries`、`agent_session_registers`、`agent_session_operations`、`agent_session_usages`、`agent_session_pending_entries`、Subject Memory audit/clear tombstone 表。
- Entry 的内联 JSON 与 Artifact payload 二选一，Worker 读取 Artifact 时校验 Hash、大小和 ready 状态；非法 Entry kind、Compaction、Operation 和 pending queue 会显式失败。
- `crates/agentx-agent-core/src/context.rs` 与 `driver.rs` 实现 system prompt、ordered External Context、Compaction Summary、retained tail、post-cut messages 的确定性投影；当前 User Message 和恢复队列 prompt 不重复。
- threshold 与 provider overflow 均使用独立 Compaction Operation、一次 overflow retry、Summary/cut snapshot 和完整历史保留；再次 overflow 返回 `AGENT_CONTEXT_OVERFLOW`。
- `services/agentx-v2-runtime/src/worker_runtime_agent_state.rs` 实现 Durable StatePort、Session Loader、Register CAS/Fencing、Usage 去重、pending 输入 32 条上限和幂等键。
- `services/agentx-v2-runtime/src/agent_session_queue.rs` 与 `workflow-runtime` recovery role 实现 durable pending wakeup：队列行绑定原 Execution/Node/Attempt，Session Register 无开放 Operation 后创建幂等 `resume_execution` 命令；Agent wakeup 使用 `ExecutionMachine::retry_waiting` 创建新 Attempt，不会把 Agent 当作已完成等待节点；恢复成功的同一事务消费 pending 行，终态执行则取消该行。
- `agent_subject_memory_audit` 与 `agent_subject_memory_clears` 是 P3-05 的 Runtime 权威清除语义。它们记录可信 Subject Scope 的审计和 tombstone，不伪装成外部 Memory Provider DELETE API；Memory 内容仍是不可信 Tool Result，禁止自动 Transcript 写入。
- `services/agentx-v2-runtime/src/query.rs` 提供受权 Session/Entry/Usage/Compaction/Recovery 和 Subject Memory 搜索/清除接口，并执行租户、Application、Subject、Agent Node 过滤和脱敏；`apps/web/src/features/agent-sessions/agent-sessions-page.tsx` 提供 Session/Compaction/Recovery/Usage/Entry、Session Clear 和 Subject Memory Audit/Clear 诊断视图。

## 4. 边界与清理

- Core 仍不依赖 SQL、HTTP、Provider、Vault、OSS、Kubernetes、文件系统或进程；所有持久化、Memory 和 Model Effect 通过 Worker Port/Adapter。
- Worker 不使用本地内存作为 Session 权威状态，不调用宿主 `std::fs` 或 `std::process::Command`。
- 未增加 migration、双写、兼容解析、fallback 或 Feature Flag；Session 表直接属于 Runtime 初始 Schema。
- P3-04 Run-scoped Memory 与 P3-05 trusted Subject Memory 使用不同 Scope 和授权证据；P3-05 不自动保存 Transcript，不实现多 Lane、Branch、Fork 或 Pi JSONL/SQLite 兼容。
- 当前 Run 的 Sandbox、临时 Namespace 和 Run 资源均由 Fixture 清理；未留下本次测试的 Session、Memory 或 Artifact 业务数据。正式 E2E 必须使用 `tests/e2e` Python 唯一入口并在 `finally` 清理。
